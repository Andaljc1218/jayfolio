## Overview

FLASH-Q is a console-based Java application designed to aid users in learning and self-assessment by creating, managing, and taking quizzes with flashcards. Built with object-oriented principles, it provides a clean text-based interface for students to study and test their knowledge.

## Problem

Students need an effective tool for self-assessment and memorization. Existing solutions are often overly complex or lack focus on simplicity. A lightweight, focused tool for flashcard-based learning was needed — something that works without a GUI and runs anywhere Java is available.

## Solution

A console-based application with a clean text interface that allows users to create, edit, and manage flashcard decks, then take randomized quizzes with scoring and performance tracking. Uses object-oriented design with clear separation between data models, storage, and the quiz engine.

## Key Features

- **Flashcard Management** — Create, edit, delete, and organize flashcard decks
- **Quiz Engine** — Generate random quizzes from deck content with multiple question modes
- **Scoring System** — Real-time scoring with performance analytics
- **Export/Import** — Save and load deck files for sharing
- **Session Tracking** — Performance history across quiz sessions

## Technology Stack

- **Language:** Java
- **Paradigm:** Object-Oriented Programming
- **Storage:** File-based serialization
- **Interface:** Console-based UI

## Development Process

Started with class design and UML diagrams. Implemented core flashcard logic first, then the quiz engine, then persistence layer. Followed a test-driven approach for the matching and scoring algorithms.

## Challenges

Designing flexible data structures for various flashcard types (text, image, multi-choice). Balancing console UI usability with the limited interface options of a terminal. Ensuring the serialization format is both human-readable and machine-parseable.

## Lessons Learned

Importance of separation of concerns in console applications. Value of iterative testing with real users. How to design clean APIs even in a console-based context. The significance of good error handling even in simple applications.

## Future Improvements
